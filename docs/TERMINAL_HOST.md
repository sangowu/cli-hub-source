# Windows terminal host

CLI Hub now separates the interface from the owner of its PTYs. Closing or updating the interface leaves live CLIs, their process IDs, working memory and tasks in the background. Reopening the interface connects to those same processes even when **Restore CLI sessions on startup** is disabled.

## Ownership and lifecycle

The installed `cli-hub.exe` is the interface. It launches a private, content-addressed copy named `cli-hub-terminal-host.exe` under the application configuration directory. The host runs the existing Rust terminal manager with a hidden native Tauri window, without a WebView, tray, updater or GUI single-instance plugin. Tauri's native window builder currently requires its `unstable` feature; Cargo.lock pins the verified API version.

The distinct executable name and location matter: the generated NSIS installer finds and closes processes by the main executable name. Updating or replacing the installed interface must not close or overwrite the running host. The host's code stays at its original version while it is running. Use **Settings → Background CLI sessions → Stop all and exit** (or the tray's equivalent) to stop tasks and the host, then reopen CLI Hub to start the host from the current interface version.

Closing the main window exits the interface and its tray. To reconnect, use the normal application shortcut. Automatic sign-in startup still starts the interface; **Start minimized** still hides that interface in its tray.

Only the host owns `PreferencesStore` and writes `preferences.json`. GUI preference commands and terminal commands are forwarded to it, preserving the existing invoke contracts and the 8-per-workspace / 24-global session limits. Explicitly stopping a session still removes its restart request. **Stop all and exit** saves restart requests before terminating processes, as before.

## Local communication

The host binds an ephemeral TCP port on `127.0.0.1`, with a 256-bit token generated by the operating system. Its endpoint, token, protocol version and PID are stored in `terminal-host.json` beside the preferences. On Windows the application directory and endpoint/preferences files use a protected ACL granting full access only to the current user, SYSTEM and Administrators. Both new and leftover temporary files are restricted before writing; existing files are repaired before reading/reconnecting, and errors block startup or preference operations. Reparse points at these paths are rejected. Do not publish or copy the endpoint file. This endpoint provides no remote access and should not be exposed through port forwarding.

Repairing ACLs does not invalidate an already copied token or close existing file handles. To rotate the token and activate new host code, finish running tasks, use **Stop all and exit**, then reopen CLI Hub. Reconnecting to an old host deliberately preserves running tasks; it repairs the known files' ACLs but does not replace the host or change its current token.

Commands use bounded newline-delimited JSON, a protocol check, authentication, read/write timeouts and at most 16 concurrent connections. The event stream has bounded queues and at most 4 subscribers. Slow clients are disconnected instead of blocking terminal output. Heartbeats and subscription cleanup release idle disconnected clients. A lost event connection shows an error and disables launches and updates until the interface reconnects by reloading/reopening; input RPC failures also surface errors. No replacement host is started while the endpoint's PID remains alive but unreachable or incompatible.

Temporary environment overrides cross IPC in memory but are excluded from saved launch requests. Terminal output stays in the host's bounded in-memory history (256 KiB per live session). Reconnection recovers that recent output, rather than a complete transcript or serialized terminal screen. The host retains only live sessions; the interface separately saves whitelisted card metadata under `cli-hub.session-records.v1` in WebView-local storage. Stopped/failed cards survive interface restart without saved output, error text, arguments or environment. Live snapshots determine running state; unmatched saved running cards become stopped, and startup relaunches reconcile with saved cards rather than duplicating them. Removing a card or workspace updates this metadata. Update installation requires a successful metadata save; invalid existing data is left untouched and blocks installation until resolved. Clearing application data removes the records.

Protocol 1 includes the existing terminal and preference command shapes plus `ping` and event subscription. Future interface releases must remain compatible with a running protocol-1 host if they promise uninterrupted updates. Breaking protocol or preference changes require an explicit host migration after its tasks finish; they must not silently replace an incompatible host.

The v0.1.10 interface adds a newline shortcut that a v0.1.9 host does not serialize. Until a supporting host saves the field, the interface retains only this key mapping in its local WebView storage (`cli-hub.newline-shortcut.v1`). It reads that fallback on reopening, without writing the host-owned preferences file. The fallback is removed after a supporting host acknowledges saving the mapping. This preserves live-session updates and stores no terminal text or credentials.

## Boundaries

- The first migration cannot transfer PTY ownership from an already-running old interface. Finish its tasks or explicitly stop them before installing the first host-enabled release.
- A computer reboot, host crash, or explicit stop ends the original processes. Optional startup restoration relaunches CLIs, and cannot recover their running tasks, conversations or temporary environment.
- The host remains resident even when idle. This is a per-user background process, not an installed Windows service.
- Windows can forbid a process from escaping an enclosing Job Object. Host startup fails rather than promising independent lifetime in that environment. Launch from the desktop to verify the normal application lifecycle.

## Verification

With Vite running on port 1420, compile the isolated application using:

```powershell
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS='--remote-debugging-port=9224'
npm run tauri -- dev --no-watch --config scripts/host-test.conf.json
```

When a test runner restricts Job Object breakaway, launch the resulting debug executable from the Windows desktop with the same debug-port environment. It must have been compiled with the isolated `com.clihub.host-test` configuration; do not run these tests against the production application.

Run `python scripts/verify_terminal_host.py prepare`, close or end only the isolated GUI process, then run `python scripts/verify_terminal_host.py detached`. Reopen that same isolated executable and run `python scripts/verify_terminal_host.py reconnected`. These phases check original host and terminal PIDs, continued PowerShell output, CMD memory, recent output, input, resize, repeated reconnects, authentication rejection, update preflight and explicit shutdown. `cleanup` shuts down only this test's host if a phase fails.

`python scripts/verify_host_update_ui.py` covers updates with active sessions: success, failed download, unavailable host, failed installer and disconnected-host blocking. It uses a mock and does not install a package.

The v0.1.9 release gate also used `host-bundle-test.conf.json`, which sets a separate identifier, product name and executable name. An installed host-enabled v0.1.8 test fixture kept a CMD memory variable and a running PowerShell task while NSIS and MSI test installers replaced its interface with v0.1.9. Original host/PTY PIDs, task output and reconnect input/resize remained intact. MSI ran in current-user mode (`ALLUSERS=""`) in the isolated install directory; system-wide administrative installation was not exercised. After explicit shutdown, the `restarted` phase checked that reopening starts the current host even while Windows retains a dead process handle. Test packages are not release assets.
